# Day 6 · Beyond Accuracy: Sensitivity, Specificity, PPV, and Prevalence

> **NOT A MEDICAL DEVICE.** Every patient in this repo is generated by it.

Day 5's cohort has a prevalence knob, so the same model can be refitted on populations differing only in how common the event is.

## The same model, five populations

```
 prevalence  accuracy    sens    spec     PPV   always-no
       0.9%     99.1%    0.0%  100.0%    0.0%       99.1%
       4.9%     95.1%    0.3%  100.0%   40.0%       95.1%
      12.0%     88.1%    3.8%   99.6%   56.3%       88.0%
      25.9%     76.5%   23.1%   95.1%   62.0%       74.1%
      39.7%     68.7%   47.8%   82.4%   64.2%       60.3%
```

Read the first and last columns together. **At 0.9% prevalence the model scores 99.1% accuracy and finds zero cases** — exactly what a model answering "no" to everybody scores, to one decimal place.

Accuracy is not a weak measure here. It is measuring the prevalence and reporting it as performance. A test asserts both halves: that the model looks excellent, and that it does not beat the trivial baseline.

## Is the model bad, or is the threshold?

```
 prevalence     AUC   sens @0.5  sens @top-k  PPV @top-k
       0.9%   0.756        0.0%         9.3%        9.3%
       4.9%   0.744        0.3%        21.4%       21.4%
      12.0%   0.735        3.8%        33.5%       33.5%
      25.9%   0.733       23.1%        48.7%       48.7%
```

The AUC barely moves. It is a ranking measure — the probability a random case scores above a random control — so it never looks at a threshold and never notices prevalence.

**The model was never the problem.** Flagging the top *k* patients, where *k* is the number of cases, recovers real sensitivity at every prevalence.

Which is also AUC's limitation: it is identical for a model that is useful in your clinic and one that is not, because what differs between them is the threshold and the population, and AUC has been carefully built to ignore both.

## PPV is a property of the population, not of the test

Hold the test fixed at 95% sensitivity and 95% specificity — numbers any paper would be pleased to report — and vary only the population:

```
 prevalence      PPV      NPV   false alarms per case  screened per case
       0.1%     1.9%   100.0%                    52.6             1052.6
       1.0%    16.1%    99.9%                     5.2              105.3
       5.0%    50.0%    99.7%                     1.0               21.1
      12.0%    72.2%    99.3%                     0.4                8.8
      30.0%    89.1%    97.7%                     0.1                3.5
      50.0%    95.0%    95.0%                     0.1                2.1
```

At one in a thousand, a 95/95 test flags **fifty-three people for every one it is right about**. The test has not changed. Nothing about it has got worse.

Sensitivity and specificity are properties of the *test*, measured on diseased and well patients separately, so neither moves with prevalence — a test tripling the well population leaves both untouched and PPV lower, and that is asserted directly.

PPV is Bayes' rule applied to both. **A paper reporting only sensitivity and specificity has said nothing about what a positive result means in your clinic.**

## What each number is for

| Measure | What it is for |
|---------|----------------|
| accuracy | Almost nothing. It tracks prevalence, and the baseline it must beat — always answering "no" — is rarely printed beside it |
| sensitivity | A property of the test. Ask it when a **miss** is the expensive error |
| specificity | A property of the test. Ask it when a **false alarm** is the expensive error |
| PPV | What a flagged patient should be told, and the only one that changes when you move the same test to a different clinic |
| NPV | What a cleared patient should be told. Comfortable at low prevalence for the same reason PPV is not |
| AUC | The model's ranking, independent of threshold and prevalence — which is its strength and the precise reason it cannot answer a clinical question |
