# Day 7 · Thresholds: Choosing Which Error You Would Rather Make

> **NOT A MEDICAL DEVICE.** Every patient in this repo is generated by it.

One model, one set of predictions, six ways to cut them.

```
rule                       cut    sens    spec     PPV  flagged  misses
0.5, the default         0.500    5.7%   99.4%   58.6%      237    2293
Youden's J               0.112   71.6%   65.1%   22.1%     7880     691
max F1                   0.177   50.9%   82.9%   29.2%     4243    1194
cost 1:1                 0.573    3.4%   99.8%   66.7%      123    2350
cost 5:1, miss worse     0.177   50.9%   82.9%   29.2%     4243    1194
cost 20:1                0.051   94.0%   30.8%   15.8%    14443     145
```

The thresholds run from 0.051 to 0.573 — a factor of eleven — and the clinic flags between **123 and 14,443** of twenty thousand patients. A factor of 117 in workload, from a model that never changed.

## Every threshold is a statement about costs

Expected cost is lowest when a patient is flagged if

```
p × miss_cost > (1 − p) × false_alarm_cost
```

so the optimal cut depends on nothing but that ratio. Reading it backwards gives the ratio any threshold has already assumed:

```
  threshold    implied miss : false alarm
      0.500                       1.0 : 1
      0.330                       2.0 : 1
      0.200                       4.0 : 1
      0.112                       7.9 : 1
      0.050                      19.0 : 1
      0.010                      99.0 : 1
```

So the six rules are not six kinds of answer. They are **six cost ratios, four of them unstated**:

```
rule                       cut     says a miss costs
0.5, the default         0.500    1.0x a false alarm
Youden's J               0.112    8.0x a false alarm
max F1                   0.177    4.6x a false alarm
cost 20:1                0.051   18.5x a false alarm
```

A team using 0.5 has decided that sending a case home undiagnosed is exactly as bad as an unnecessary biopsy. Nobody says that sentence out loud, and it is what they shipped.

### A bug this section had

`implied_cost_ratio` first returned `t / (1 − t)` — the reciprocal of what its own name and docstring described. Every other test passed; the one that caught it asserts that `threshold_for_cost_ratio` and `implied_cost_ratio` are **exact inverses**, which they now are to nine places.

## So state the ratio and let it choose

```
  miss : false alarm  threshold    sens     PPV  flagged  misses
               1 : 1      0.500    5.7%   58.6%      237    2293
               2 : 1      0.333   19.7%   43.4%     1106    1952
               5 : 1      0.167   53.4%   27.9%     4654    1133
              10 : 1      0.091   79.8%   20.0%     9691     492
              20 : 1      0.048   94.8%   15.4%    14970     126
              50 : 1      0.020   99.4%   12.7%    18995      15
```

The same table as the first one, with the hidden input made visible. **Nothing here is a statistical question** — somebody has to say what a missed case costs relative to a false alarm, and no amount of ROC curve will say it for them.

## The ratio moves the cut further than the model does

Total cost on this cohort under three beliefs about what the errors cost. Best cut per column marked:

```
  threshold           1:1           5:1          20:1
      0.500        2,391*       11,563        45,958
      0.330        2,597        10,361        39,476
      0.200        3,747         9,183*       29,568
      0.112        6,818         9,594        20,004
      0.050       12,486        13,054        15,184*
```

The best threshold moves from 0.5 to 0.05 across those three columns, and **the cost of using the wrong one is larger than any difference this repo has measured between models.**

## A note on `max F1`

It is popular and it has no clinical interpretation: there is no cost ratio under which maximising F1 is the right decision, because F1 is not a linear function of the four counts. It happens to land at 4.6:1 here, and that is a coincidence of this cohort rather than a claim about anything.
