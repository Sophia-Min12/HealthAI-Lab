# Day 9 · Missing Data, and the Ways Imputation Lies

> **NOT A MEDICAL DEVICE.** Every patient in this repo is generated by it.

Three mechanisms — a coin flip, a pattern driven by an observed feature, and a pattern driven by the value that is gone — and four ways of coping with each.

```
MCAR - a coin flip: 40% missing, observed mean +1.602 against a true +1.603
  handling                    coefficient   error     AUC
  complete cases                    0.321   0.021   0.799
  mean imputation                   0.162   0.138   0.788
  conditional imputation            0.317   0.017   0.791
  indicator, then mean              0.186   0.114   0.788

MNAR - driven by the value: 42% missing, observed mean +2.255 vs true +1.603
  complete cases                    0.317   0.017   0.780
  mean imputation                   0.223   0.077   0.789
  conditional imputation            0.323   0.023   0.791
  indicator, then mean              0.221   0.079   0.789
```

**Mean imputation halves the coefficient under MCAR** — 0.162 against a true 0.300 — with nothing informative about the missingness at all. Every imputed patient is placed at the centre of the distribution, so the column's spread falls while no signal is added, and a coefficient is a covariance over a variance.

Conditional imputation recovers it. The reason is in the header: age correlates **0.80** with cholesterol here. On a cohort where the other features do not predict the missing one, conditional imputation *is* mean imputation with extra steps — measured as a maximum difference of 0.2 between the two imputed columns, and pinned by a test.

## So where does MNAR actually hurt?

The coefficient survived MNAR above, because the fit conditions on the other features. Split the patients by whether their value was kept:

```
MCAR
  group                 n  true risk  predicted     gap
  value observed    11936      0.121      0.125   0.004
  value missing      8064      0.119      0.120   0.002
  imputed +1.608 against the true hidden +1.604

MNAR
  value observed    11502      0.151      0.149  -0.001
  value missing      8498      0.078      0.088   0.009
  imputed +1.339 against the true hidden +0.721
```

Under MCAR the imputer fills +1.608 where the truth was +1.604. **Under MNAR it fills +1.339 where the truth was +0.721.**

The missing values were the low ones — the test was not ordered because nobody expected it to be abnormal — and no feature says so, because the thing that caused the pattern is the thing that is gone. The imputer invents values that are systematically too high, and the patients it invents them for are over-predicted.

**That damage is invisible in the overall coefficient and in the overall AUC.** It is visible only when the group is looked at on its own, which is not what a summary table does.

## And missingness is itself a predictor

```
mechanism     event rate, missing    observed    indicator coefficient
MCAR                        12.2%       12.4%                    0.138
MNAR                         8.3%       15.3%                   -0.140
```

Under MNAR, patients with no cholesterol result have an event rate of **8.3% against 15.3%**. The absence of a test nearly halves the risk, and a model given the indicator picks that up.

This is usually presented as a reason to add the indicator, and it works. What the model has learned is that **this hospital orders cholesterol panels when it is worried.** Move it to a hospital that orders them on everybody, and the coefficient is applied to a population where it means nothing — with no error and no warning.

The indicator is a good idea *and* it encodes a fact about a workflow rather than about a patient. Both halves are true and only the first is usually said.

### A silent bug worth keeping

`add_missing_indicator` must be called **before** imputing. Afterwards there are no NaNs left, so the indicator is a column of zeros: present, harmless-looking, carrying nothing. The first version of this demo did it in the wrong order and all three imputation strategies produced identical coefficients to three decimal places. The function now raises rather than returning that column.
