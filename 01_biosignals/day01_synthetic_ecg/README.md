# Day 1 · A Synthetic ECG, and Why Synthetic Is the Honest Choice

> **NOT A MEDICAL DEVICE.** Every signal in this repo is generated by this file. No patient data appears anywhere.

Every later day in Level 1 detects something in this signal, so the signal comes first — and it is **generated, not downloaded**.

## Why generate it

That is not a shortcut around a licensing problem. It is the only way to have **exact ground truth**.

When Day 4's R-peak detector reports 74 beats, the question is whether those are *the* beats. Only a signal whose peak positions were written down at generation time can answer that. A public ECG database ships with expert annotations that are themselves estimates — made by people who disagreed with each other, on recordings where the truth is genuinely ambiguous.

So `synthesise_ecg` returns `(signal, r_peak_samples)`, and every detector in this repo is scored against that second array rather than against its own output.

```
R peaks at samples: [52, 260, 469, 677, 885, 1094, 1302, 1510] ...
spacing:            [208, 209, 208, 208, 209, 208, 208] samples
```

A test verifies the ground truth is actually true — that the signal really does peak at each reported position — because everything downstream is scored against it, and a lie there would propagate silently through the whole level.

## The waveform is a deliberate caricature

Five Gaussian bumps: a small upright P, a sharp tall R flanked by negative Q and S, a broad low T. Amplitudes in millivolts, shaped to resemble lead II.

```
 0.04s  +0.12 ########          <- P wave
 0.18s  +0.00 ######
 0.20s  +1.18 ##############################   <- R
 0.22s  -0.12 ####              <- S
```

It is not a physiological model, it will not fool a cardiologist, and it is entirely sufficient for testing a peak finder. That is the honest description of what most "synthetic ECG" code is for, and saying so up front is better than implying more.

Tests check the *shape* rather than the numbers: R is the maximum, it dominates everything outside the QRS by more than 3×, there are genuine negative deflections (a waveform that is all positive has lost the QRS), and the trace starts and ends near baseline.

## Heart rate variability

```
hrv=0.00s  mean RR 0.833s  sd 0.0019s  rate 72.0 bpm
hrv=0.02s  mean RR 0.832s  sd 0.0172s  rate 72.1 bpm
hrv=0.05s  mean RR 0.830s  sd 0.0425s  rate 72.3 bpm
```

At `hrv=0` the rhythm is metronomic — which is **unphysiological**. A real heart is never perfectly regular, and reduced variability is itself a clinical finding rather than a sign of health. Day 4 uses a non-zero value; Day 1 keeps both so the difference is visible.

## Rate comes from intervals, not from a count

```
count / duration : 72.7 bpm
from intervals   : 60.0 bpm  (correct)
```

On a 3.3-second recording of a 60 bpm rhythm, dividing beats by duration is off by more than 20%. The two agree only when the recording starts and ends exactly on a beat, which no recording does. `heart_rate` uses `60 / mean(diff(peaks))`, which is what a monitor reports, and a test pins that the naive form is wrong by more than 5 bpm on exactly this case.

## SNR exists only because the clean signal does

```
noise sd 0.01 mV -> SNR   25.6 dB
noise sd 0.05 mV -> SNR   11.6 dB
noise sd 0.20 mV -> SNR   -0.6 dB
```

This number is **not computable on real data**, because the clean signal is not available. Every claim that a filter "improved the signal" on a real recording is therefore an opinion supported by a picture.

That is the second argument for synthesis, and it is the one that matters on Day 3: when the moving-average filter is applied, its effect can be stated as a number rather than shown as a before-and-after plot.

## Run it

```bash
# demo (a beat rendered as text, ground truth, HRV, SNR)
python ecg.py

# tests — from the repo root (what CI runs)
pytest
python -m unittest discover -s 01_biosignals/day01_synthetic_ecg

# tests — from inside this folder
python -m unittest
python test_ecg.py

# the docstring examples are runnable too
python -m doctest ecg.py
```

> ⚠ Bare `python -m unittest discover` from the repo **root** silently finds zero tests with this layout — use one of the commands above.

## Where this leads

**Day 2** adds the three noises that actually corrupt an ECG — baseline wander from breathing, mains hum at 50/60 Hz, and motion artefact — each with a known amplitude, so Day 3's filter can be scored in decibels. **Day 4** then detects the R peaks and is graded against the array this file already wrote down.
